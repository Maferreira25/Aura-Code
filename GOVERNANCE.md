# Governance — Draft

Version 0.1 uses maintainer-led governance while the contributor community forms.

## Project Maintainers

- **Lead Maintainer:** [@Maferreira25](https://github.com/Maferreira25)

## Principles

- normative changes require public pull-request review;
- evidence and rationale are part of the change;
- no vendor/model receives privileged normative status;
- conflicts of interest should be disclosed for normative proposals;
- backwards-incompatible control semantics require a versioned release note;
- security fixes to framework tooling may use a private disclosure path before publication.

## Evolution Toward 1.0

Before 1.0, governance will formalize:
- expanded maintainer committee;
- voting/consensus rule;
- release manager;
- security response team;
- appeal process for normative control changes;
- cadence for standards/research refresh.
