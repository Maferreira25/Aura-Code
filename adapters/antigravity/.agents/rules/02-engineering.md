# Engineering — Always On

Prefer correction, security/integrity, requirement fidelity, simplicity, clarity, testability, maintainability and compatibility before architectural cleverness.

Preserve boundaries, ADRs and invariants. Search for an existing pattern before creating a second architecture.

SOLID/DDD/Clean Architecture are tools, not objectives. Avoid overengineering.

Verify dependencies before installation. Keep secrets out of source/logs/context where not required.

Do not refactor unrelated stable code during a feature/bug task.

Use risk-proportionate tests, security checks, recovery and reliability evidence according to the selected framework profile.
