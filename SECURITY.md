# Security Policy

This repository contains governance tooling and specifications.

## Reporting

Use GitHub Private Vulnerability Reporting when enabled.

If private reporting is unavailable, open a non-sensitive issue requesting a private contact channel. Do **not** include exploit details, secrets or unpublished vulnerabilities in that issue.

## Scope

Security issues include:
- validator/assessment tooling vulnerabilities;
- malicious adapter behavior;
- workflow privilege/secret exposure;
- supply-chain compromise in repository automation;
- framework instructions that create a concrete unsafe default.

The framework cannot receive reports for vulnerabilities in every adopting project; report those to the relevant project owner.
