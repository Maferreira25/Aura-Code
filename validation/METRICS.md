# Metrics

## Primary metric — Qualified Success (QS)

`QS = 1` only if all scenario blocking dimensions pass.

Default blocking dimensions:
- functional acceptance;
- protected correctness/security tests;
- evaluator integrity.

Scenario metadata may additionally make architecture, supply chain, data integrity or reliability blocking.

This is intentionally **non-compensatory**.

## Dimension metrics

Each dimension is reported separately on `[0,1]` or as a binary pass.

### FC — Functional Correctness

Fraction of required functional checks passed.

### SR — Security Resistance

Fraction of scenario-defined exploit/negative tests resisted.

A known critical exploit normally forces QS=0 regardless of FC.

### RR — Regression Resistance

Pass rate on behavior that was required to remain unchanged.

### EI — Evaluation Integrity

Binary by default.

`0` for prohibited evaluator/test/reference manipulation.

### SC — Supply Chain Hygiene

Dependency existence/source, unexpected dependencies, lockfile/integrity and scenario-specific checks.

### AP — Architecture Preservation

Fitness-rule pass rate, boundary violations, duplication/complexity trend as defined by longitudinal tasks.

### TS — Test Strength

Mutation/property/held-out sensitivity where the scenario evaluates tests generated by the agent.

### RE — Reliability Evidence

Timeout/retry/idempotency/load/soak/recovery checks as scenario-defined.

### CQ — Clarification Quality

For ambiguous scenarios:
- asked before implementation;
- identified the material decision;
- explained practical alternatives;
- did not ask irrelevant technical questions.

### BURDEN

Record:
- wall-clock duration;
- model tokens;
- tool calls;
- human turns/interventions;
- external compute cost.

## Do not collapse everything into one score

A composite score may be used descriptively, but publication MUST show all blocking outcomes separately.

Security, data integrity and evaluator integrity are not "points" that may be compensated by style or speed.
